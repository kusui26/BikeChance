# 天気予報のテスト用フィクスチャ

`apps/ml` の天気の取り込み（`jobs/weather_archive.py`）が読むテストデータ。

## 出どころ

**本番の Storage（`weather-raw`）に保存された生ファイル**から作っている。Open-Meteo から
取り直すのではなく、実際にアーカイブしたものを使う（`fixtures/gbfs/` と同じ方針）。

```
jma_msm_sample.json.gz   ← 2026/09/10/jma_msm_1789002000_00.json.gz の縮約
```

## 縮約の方針

| 何を | 扱い | 理由 |
|---|---|---|
| 地点 | 100 → **2 件** | 読み方の検査に地点数は要らない。1 ファイル 40 KB を 880 B に落とす |
| 時系列 | 72 → **24 時間** | 発行時刻から 8 時間ぶん（`WEATHER_LEAD_HOURS`）読めれば足りる |
| 列 | **落とさない** | `best_match` も `precipitation_probability` の null も残す |

## 残してある癖（縮約後も存在することをテストが確認する）

- **`hourly.time` は JST のナイーブ文字列**（`2026-09-10T00:00`）。UTC と読み違えると 9 時間ずれる
- **先頭は取得した日の JST 00:00**。発行時刻ではないので、対応する添字は毎回数える
- **`precipitation_probability_jma_msm` は全件 null**（JMA のモデルは降水確率を返さない）
- **`best_match` の列が並んでいる**（`jma_msm` だけを読んでいることの検査に使う）

## 作り直し方

```bash
# 本番 Storage から 1 ファイル取り、2 地点 × 24 時間に切る
# （切り方は W4 プラン §6.4 に書いた手順と同じ）
```
