# モデルカード

**登録する版には必ずカードを付ける**（CLAUDE.md §6、開発プラン §7.3）。カードは当てはめのジョブが書く（手で書き起こさない）。

| 版 | 書くもの | 置き場所 |
|---|---|---|
| LightGBM（`lgbm-v1-…`） | `jobs/fit_lightgbm.py` の `render_card`（`--card`） | `docs/model_cards/<版>.md` |
| 合成器（`composite-v1-…`） | `jobs/build_composite.py` の `render_card`（`--card`） | 同上 |

**LightGBM v1 のカードに載るもの**（W6 の PR F）：候補（本数と学習率）・分割・門の相手の B3 の日、学習に使ったデータ（天気の被覆と、`features/` の各日の SHA-256。W6-17）、配信の実装との一致（`Booster.predict` との照合。W4-19）、門（セル単位で越えた数・配る形の改善・森を歩く行・門の表の場所）、校正（ECE。W6-15）、意思決定の指標（`precision@0.9`・`coverage@0.9`・3 段階の実現率。W6-16）、門を当てる前の単体の Brier、既知の限界、試し打ちの仕方。

**合成器のカードに載るもの**（W6 の PR H）：作った時刻と SHA-256、特徴量の版、学習日（B3 と LightGBM の和集合。鮮度の警報は B3 の最終学習日で鳴る）と LightGBM の最終学習日、部品（B3・森・門の表）の版と SHA-256、門（系統 × ターゲットごとに森を歩くセルと表のセル、決めた検証日、**shadow で削ったセル**）、**境目の差**（|P_LGBM − P_B3| の分布。W6 プラン §5.10）、配り方（プロファイルの無い周期は全セル B3、確度の規則、確かめ方）。

**`--register` はカードが無ければ当てはめる前に止まり、カードを書いてから登録する。** 登録簿の `card_path` は、リポジトリからの相対パス（`docs/model_cards/<版>.md`）を指す。

**Actions（`fit-lightgbm.yml`）で登録した回**は、カードがランナーの中にしか無い（ワークフローはリポジトリに書かない）。記録と要約に全文が出るので、**その日のうちに `docs/model_cards/<版>.md` としてコミットする**（W6 プラン §7.4）。
