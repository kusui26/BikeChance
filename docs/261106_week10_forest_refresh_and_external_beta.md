## 1. W10 のゴールと完了条件

**ゴール：新しい森と水平単位の門を 1 つの合成器にして shadow 3 日を通し、11/16 の森の鮮度の警報の前に入れ替える。あわせて、W9 から回した長期の傾向（PR B）を配り、TestFlight の外部ベータ（M6）を出す。**

**W10 の主題は 4 つ。**

1. **森の入れ替えと門の単位**（D-33 の直し）：当てはめに水平単位の門を足し（PR A）、新しい森を 50 本と 70 本で測って選び、合成器を組んで shadow 3 日 → 昇格
2. **長期の傾向**（W9 の PR B）：11/11 に入れ、`/v1` の詳細が `trend` を返し、iOS-5（ヒートマップ）を本番の応答の契約テストつきで出す
3. **外部ベータ（M6）**：3 つ目のビルド（重なる印・傾向・AX5 の直し）を、招待した外部のテスターに。プライバシーポリシーとサポートの頁を用意する
4. **ドリフト監視の準備**：主要特徴量の PSI を測って閾値を決める（実装は W11）

### 242（11/8）：アプリが送るのは地図の範囲だけではない。開いたポート・お気に入り・行程の内容も、要求の記録に 30 日残る

**見つけ方**：プライバシーポリシー（W10-07）を書くために、アプリが送るものと残る場所を確かめ直した（所見 218 の規則：「保持しない」は通り道でも確かめてから言う）。

**送っているもの**（iOS の `V1Client`）：

**残る場所**：Vercel の要求の記録は検索の条件（クエリ）・User-Agent を持ち、Observability Plus で **30 日**（公式文書の Runtime Logs）。`/v1` は Supabase に PostgREST で問い合わせ、**範囲の条件とポートの識別子がクエリに載る**ので、Supabase の API の記録（`request.search`）にも **7 日**残る（料金表の「Log retention (API & Database)」。問い合わせ元は `/v1` の関数なので、利用者の IP アドレスは載らない）。自前の表には残さない。現在地の座標・お気に入りの一覧の保存は端末の中だけ。所要の計算（`MKDirections`。出発と到着のポートの位置）と目的地の検索（`MKLocalSearchCompleter`。入力した文字と地図の範囲）は Apple に送る。
