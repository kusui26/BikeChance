## 0.4 裏付けに測ったこと——**同じ関数を呼び、1 か所ずつ変えた**

§0 と §0.1 の「なぜ」を確かめるために、`evaluate_baselines` と `fit_baseline` が呼ぶ関数（`conditional.fit` → `source.table` → `conditional.predict_leave_one_out` → `source.leave_out` → `blend.fit`）を**そのまま呼び、1 か所だけ変えて**当てはめ直した（リポジトリの外のスクリプト。方法は §12）。**変えない場合の係数と Brier は、報告書と成果物に表示の桁（係数 3 桁・Brier 5 桁）で一致した。**

**測り方**：

- **A・C**：`evaluate_baselines.prepare`（`--from 2026-09-15 --to 2026-09-23 --eval-days 1 --purge-days 1`）で読み、`eval/harness.py` の `_fit_target` の中身を同じ順に呼ぶ。「B2 を落とす」は同じ係数で `blend.design(b1, b1, h)`（B2 が引けないセルで配信が出す値）。「学習側の下限 2」は `source.leave_out` に渡す表の `min_days` だけを 2 にした（配る側の `usable` は 3 のまま）。「到着日で引く」は `own_day` と同じ引き方で、引く日だけを `day + (minute_of_day + h_min ≥ 1440)` にし、到着日が `dailies` に無ければ引かない

- **EDA #7 §6 との違い**：あちらは本番の全数（`forecast_log`・`x1000`）、こちらは評価の行（一様 1%）の丸める前の確率。**桁ではなく向きと大きさで比べる**
