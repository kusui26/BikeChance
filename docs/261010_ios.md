## 2. 署名のチーム（10/10）

- 利用者が Xcode の **Signing & Capabilities** で Team を選んだ（Automatically manage signing のまま）。`project.pbxproj` の Debug・Release に **`DEVELOPMENT_TEAM`**（10 桁のチーム ID）が入った。チーム ID は秘密ではない（配った `.app` の署名に載る）が、要る場所（`project.pbxproj`）のほかには書かない
- **保存のときに Xcode が `project.pbxproj` を標準の書式に整え直した**（項目の並び替え・空の欄の省略）。手で書いたファイルだったため差分は大きいが、**解決したビルド設定（Debug・Release とも約 570 項目）を前後で比べると、違いは `DEVELOPMENT_TEAM` だけ**だった
- **実機向けの署名つきビルドが通った**（`generic/platform=iOS`、Debug と Release）。署名は Apple Development の証明書、プロビジョニングプロファイルは Xcode が管理するチームのもの（`iOS Team Provisioning Profile: *`）
  - **ワイルドカード（`*`）のプロファイルで署名された**ので、Bundle ID `app.bikechance.BikeChance` は、まだ明示の App ID として登録されていない見込みだった
  - → **見込みどおりだった（10/11）**：App Store Connect の「新規 App」のバンドル ID の一覧に出なかった。この Mac の署名ファイルを見ると、BikeChance 用はワイルドカードの `iOS Team Provisioning Profile: *` だけで、`app.bikechance.BikeChance` 専用のものは無かった。**BikeChance は entitlements（プッシュ通知・アプリグループなど）を持たないので、Xcode の自動署名は ID を登録せずにワイルドカードで済ませる**。反映待ちではなく、未登録が原因だった
  - **手で登録した（10/11、利用者）**：§4 の手順 2 のとおり、Identifiers に明示の App ID（`app.bikechance.BikeChance`、Capabilities なし）を登録した。Xcode とリポジトリは変えない（次に Xcode で実機向けにビルドすると、専用の署名ファイルを Xcode が自動で作る見込み。作られなくても、配布の Archive のときに作る）

## 3. アイコン

### 3.1 条件

| | |
|---|---|
| 大きさ | **1024 × 1024 ピクセルの 1 枚**。ほかの大きさは Xcode が作る（`AppIcon.appiconset` は 1 枠だけの Single Size） |
| 形式 | PNG、**透過の欄なし**（あるとアップロードの検証で止まる）、sRGB |
| 角 | **丸めない**（iOS が丸める） |
| 読みやすさ | ホーム画面の 60 ピクセル前後、設定の一覧の 40 ピクセル前後でも形が分かること。文字は入れない |

### 3.2 考え方

- **2 つの車輪が、それぞれ確率のゲージになった自転車**：後輪（左）が「借りられる確率」、前輪（右）が「返せる確率」。色の付いた弧が確率で、薄く残る部分が足りないぶん。アプリの中心の価値（到着したときに借りられる・返せる確率を、降水確率のように示す）を、シェアサイクルの自転車そのものに重ねた
- 弧は 12 時から時計回りで、長さは後輪 78%・前輪 56%。2 つの確率が別々に動くことを見せるための値で、数字そのものに意味は無い
- **採用：紺 `#0E2235` の地に、後輪の弧は青 `#4AA8FF`（借りられる）、前輪の弧は橙 `#FFA53D`（返せる）、フレームは白**。地図の色分け（借りられるだけ＝青、返せるだけ＝橙）と合う。**利用者が 2 案から選んだ（10/11）**
- 別案（採らなかった）：緑 `#168E67` の地に白（弧もフレームも白）。アプリのアクセント色（`AccentColor`、`#1D9C73`）を少し深くして、白との対比を 3.47 → 4.12 に上げたもの
- 紺の弱いところ：**暗い壁紙の上では、アイコンの縁が溶けて見えにくい**（§3.4 の小さな大きさの確かめ）。気になれば、地を少し明るい紺にする（§3.6）

### 3.3 形（1024 の正方形での寸法）

| 部分 | 値 |
|---|---|
| 車輪 | 中心 (300, 574) と (724, 574)、半径 150、輪の太さ 52。残りの部分は白 16%（緑の案は 24%） |
| フレーム | 太さ 36（サドルだけ 44）、端と角は丸い。ハブは半径 20 の点 |
| 全体 | 正方形の中心で 1.08 倍（自転車の幅が正方形の約 82%）。サドルの上から車輪の下までが、縦の真ん中に来る |

元の SVG は付録 A。

### 3.4 作り方と確かめたこと

- **Claude Design のキャンバス**：https://claude.ai/artifact/EBzpwetwoNH6ShUBh7kqD6 。緑の案・紺の案（採用）・小さな大きさでの見え方の 3 枚。**非公開**で、ほかの人に見せるときはページの Share から共有する
- PNG は、付録 A の SVG を 1024 ピクセルで描き、**透過の欄を外して**（RGB で）保存した。リポジトリに入れるのは PNG だけ
- 確かめたこと
  - `sips`：1024 × 1024、`hasAlpha: no`、RGB
  - 小さな大きさ（180・120・87・60・40 ピクセル）を iOS の角丸で切り抜き、明るい壁紙と暗い壁紙に並べた → どちらの案も 40 ピクセルまで自転車と読める。**紺は暗い壁紙で縁が溶ける**（緑は溶けない）
  - Release の実機向けビルド（署名つき）：`actool` の警告なし。Info.plist に `CFBundleIconName = AppIcon`、`Assets.car` に 1024 の不透明なアイコンが入る。ビルドしたアプリの 60pt@2x（120 ピクセル）も紺だった
  - 付録 A の改行した SVG を描くと、入れた PNG と 1 画素も違わない

### 3.5 入れたもの

- **入れた（10/11、#147 の 50f18e0）**：`apps/ios/BikeChance/Assets.xcassets/AppIcon.appiconset/AppIcon-1024.png` を置き、同じフォルダの `Contents.json` の枠に `"filename" : "AppIcon-1024.png"` を足した
- 変えるときは付録 A の SVG を直して描き直し、§3.4 と同じく大きさと `hasAlpha: no` を確かめる

### 3.6 これから（任意）

- **暗い壁紙での見え方**：地を少し明るい紺（たとえば `#15304A`）にすると、暗い壁紙との境が出る。TestFlight で実際の壁紙に置いて気になったら直す
- iOS 18 以降のダーク・ティントの別画像（AppIcon の Appearances）、iOS 26 の Liquid Glass 向けの層つきアイコン（Xcode の Icon Composer）。**1 枚の PNG でも表示はされる**ので、TestFlight の前には要らない

## 4. App Store Connect のアプリ（10/16 まで）→ ✅ 10/11 に作った

**結果（10/11、利用者）**：**Bundle ID を登録してから、App Store Connect にアプリを作った**。下の手順のうち、手順 2（Bundle ID の登録）が**要った**——登録する前は、「新規 App」のバンドル ID の一覧に `app.bikechance.BikeChance` が出なかった（原因は §2）。アプリの名前と SKU は、App Store Connect に入れたとおり。

**次に作るときのために**：Xcode の自動署名は、entitlements の無いアプリでは App ID を登録しない。**App Store Connect でアプリを作る前に、Identifiers で明示の App ID を登録する**（反映待ちでは出てこない）。

以下は、行った手順の控え。

**先に決めること**：**アプリの名前**（App Store に出る名前。30 文字以内、ほかのアプリと同じ名前は使えない。申請までは変えられる）。

1. https://appstoreconnect.apple.com にサインインし、「同意が必要な契約」の表示があれば先に同意する（**ビジネス**の画面）
2. **Bundle ID を登録する**（App Store Connect の一覧に無いとき。**今回は要った**）：https://developer.apple.com/account → **Certificates, Identifiers & Profiles** → **Identifiers** → ＋ → **App IDs** → **App** → 説明に `BikeChance`、Bundle ID は **Explicit** で `app.bikechance.BikeChance` → Continue → Register
3. **アプリ** → 左上の **＋** → **新規 App**

   | 欄 | 入れるもの |
   |---|---|
   | プラットフォーム | iOS |
   | 名前 | 決めたアプリの名前 |
   | プライマリ言語 | 日本語 |
   | バンドル ID | `app.bikechance.BikeChance` |
   | SKU | 自分用の管理番号。たとえば `bikechance-ios`（**あとから変えられない**） |
   | ユーザアクセス | フルアクセス |

4. **作成**。TestFlight のテスターは、最初のアップロード（W7）のあとで設定する

**うまくいかないとき**：登録で「An App ID with Identifier '…' is not available」と出たら、その ID はほかの開発者が使っている（Bundle ID を変える。`project.pbxproj` の変更と確かめのやり直しが要る）。登録できたのに一覧に出なければ、ページを再読み込みし、App Store Connect の右上のチームが Xcode で選んだチームと同じかを確かめる

- このアプリは **iPhone 専用**（`TARGETED_DEVICE_FAMILY = 1`）なので、iPad のスクリーンショットは要らない（ビルドに iPad 用の小さな画像ができるのは Xcode の既定の動き）
- Apple シリコンの Mac で iPhone 版を動かす設定は既定のまま（`SUPPORTS_MAC_DESIGNED_FOR_IPHONE_IPAD = YES`）。出したくなければ、App Store Connect の「価格および配信状況」で外せる

## 5. 端末での確認（10/15 まで。iPhone 17 Pro。開発プラン §9.6）

### 5.1 準備（1 回だけ）

1. iPhone をケーブルで Mac につなぎ、「このコンピュータを信頼しますか」で **信頼**
2. iPhone の **設定 → プライバシーとセキュリティ → デベロッパモード** をオンにして再起動（この項目は、一度 Xcode につなぐと出てくる）
3. Xcode で PR K の枝（`feat/w6-k-testflight-prep`。10/15 に PR K をマージした後は main）のプロジェクトを開き、上部の実行先で自分の iPhone を選んで **⌘R**。アプリは本番の `/v1` につながる

### 5.2 確かめる 3 つ

| | 確かめること | やり方 | 合格 |
|---|---|---|---|
| ① | **自転車の所要時間**（`calculateETA(.cycling)`） | 地図でポートを押す → **「ここから行程をチェック」** → 行き先のポートを選ぶ。**近い（1 km 前後）・中くらい（3〜5 km）・遠い（10 km 前後）**の 3 組と、別の街で 1 組 | 「**直線距離からの概算です。…**」の但し書きが**出ない**（出たら、端末の経路計算が使えなかったということ）。分数が、Apple のマップで同じ 2 地点を**自転車**で経路検索した時間とおおむね合う |
| ② | **地図のなめらかさ**（約 300 マーカー） | 都心（渋谷・新宿・千代田区あたり）でポートがたくさん出るまで縮小し、10 秒ほど続けて動かす・拡大縮小する | 引っかかりやカクつきが目立たない。目立つなら、地図の作り方を `MKMapView` に切り替える案（開発プラン §9.6）を相談する |
| ③ | **位置情報の許可** | 地図の上の**現在地のボタン（矢印）**を押す | 許可を求める画面に利用目的の文が出る。**「App の使用中は許可」**で地図が現在地へ動く。「許可しない」でもアプリが使える（設定から許可を戻して試せる） |
