- プロダクト名: BikeChance
- データリソース: HELLO CYCLING / ドコモ・バイクシェア のODPT/GBFSの公開データ
    - HELLO CYCLING: https://ckan.odpt.org/dataset/c_bikeshare_gbfs-openstreet
    - ドコモ・バイクシェア: https://ckan.odpt.org/dataset/c_bikeshare_gbfs-d-nationwide-bikeshare
- アプリの目的: シェアサイクルが希望の時刻/現地到着時刻に借りられるかどうか/返却できるかどうかをユーザーに提供する
- iPhoneアプリ/スマートフォン用のWebアプリ。iPhoneアプリを優先してください。
- 上記のODPT/GBFSのリアルタイムデータを蓄積して、学習データとして、予測モデルを構築する
- 希望の時刻/現地到着時刻に何台あるか、または、借りられる/返却できる確率（1台以上残っている/返却できる）を表示する。どちらのアプローチ、UI/UXにするかを今後あなた（Claude Code）と検討していく
- 確率を表示する場合、Accuracyだけでなく確率校正（Calibration）とBrier Score等を重視する。
- 時系列データの評価でランダムsplitをしない。未来情報リークを必ず防ぐ。
- 初期モデルはLightGBMを第一候補とし、LSTM/Transformer/GNN等はベースラインを上回る根拠が得られてから導入する。
- 特徴量は徹底的に考えていき、モデル精度を見ながら、ブラッシュアップさせていく。
- 全ポート、全地域共通のGlobal Modelを想定。具体的にはデータ（データ容量含む）を確認して決めていく。
- 開発環境/本番環境
    - 開発環境はこのMacBookAirで、このディレクトリ
    - 本番環境はVercel Hobby,Supabase proを想定
    - 他にツールとして、Google Colab pro+、Google Dreive(2TB)がある
    - iPhoneの実機はiPhone17 pro
    - 全体のアーキテクチャー、どこでデータをどのような形式で蓄積して、どこで学習データを構築して、どこで推論して、どうアプリに表示するかは、今後あなた（Claude Code）と検討していく
    - 蓄積するデータ容量を考慮して、どこででデータをどのような形式で蓄積するかを考えてください。
    - データの蓄積がモデル構築の肝になるので、データの蓄積環境の構築、蓄積の実行を最優先事項にしてください。
- HELLO CYCLING / ドコモ・バイクシェアに関するデータは、すべてチェックして、どういうデータリソースがあり、各データはどういう意味かを整理する必要がある。
- 上記のデータリソースに予約情報があるかを確認する必要がある。
- データ取集の周期は5分を想定。具体的にはデータ（データ容量含む）を確認して決めていく。
- 推論アーキテクチャは、サーバ側で一括先回りして推論することを想定。アプリはDBを読むだけ。具体的な推論周期やどの未来のレンジまでを予測するかは、あなた（Claude Code）と検討していく
- 再学習の方針もあなた（Claude Code）と検討していく
- ODPTデータ提供者のライセンス、クレジット表示、利用条件を必ず守る。
- 公共交通オープンデータセンター（ODPT）のアクセストークンは、.envのODPT_ACCESS_TOKENを使ってください。
